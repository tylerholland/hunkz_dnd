# Frontend reference

Full component-by-component detail for `src/`. Read the relevant section before editing a file named below — CLAUDE.md only keeps the short version. This file is not required reading for unrelated frontend work.

- `src/components/CharacterSheet.jsx` — Orchestrator component (~800 lines): owns sheet state, auth/unlock flow, save/create/import/export, and session sync; delegates rendering to `CharacterSheetViewMode` and `CharacterSheetEditMode`. The old ~2500-line monolith was decomposed into `src/features/characterSheet/`:
  - `CharacterSheetViewMode.jsx` (~1900 lines) — all view-mode rendering, including the four-tab structure below
  - `CharacterSheetEditMode.jsx` (~650 lines) — edit-mode form sections
  - `theme.jsx` — `PALETTES` named color themes; exported and used by pages for theming
  - `constants.js` — `BLANK_CHARACTER` (canonical default shape for new characters; includes `inspiration: false`), `parseModInt` (strict integer parser using `/^[+-]?\d+$/` to reject dice notation, preventing `parseInt("1d8") === 1` false positives), `MOD_ATTRIBUTES`, `normalizeSpells()` (Story 56 — legacy `string[]` → structured spell object tolerance, ADR-024), `buildAttackEntries({ weapons, spells })` (Story 56 — merges equipped weapons + `role: "attack"` spells into one weapons-first reference list)
  - `ItemEditorModal.jsx` — modal for editing weapons/equipment items
  - Ability score modifiers are computed on-the-fly as `floor((score-10)/2) + item bonuses`, never stored
  - **Four-tab structure** (view mode): `"loadout"` (Inventory), `"persona"` (Persona), `"combat"` (Combat), `"map"` (Map); active tab stored in `sessionStorage` as `dnd_tab_${slug}`, default `"combat"`. Map tab dimmed/disabled when no active map.
  - **Combat tab**: concentration banner, inspiration toggle, condition grid + exhaustion counter, spell slots, weapons quick-reference, **Session Notes** (player notes with per-note share toggle), dice roller — all writable without auth via `patchSession`
  - **Persona tab**: renders the `inPlay[]` trait list with diamond bullet points
  - **Inventory tab**: two-column weapons + equipment grid (`.loadout-grid`)
- `src/components/DiceRoller.jsx` — Self-contained dice roller component. Props: `{ weapons, stats, pal, slug, onAdvModeChange? }`. Renders at the bottom of the Combat tab. Owns its own state (roll results, history, advantage mode, free picker state). Broadcasts resolved rolls to the shared roll-history feed via `postCharacterRoll` (fire-and-forget; UI never blocks on it). Key internals: `parseDiceExpr(str)` pure parser (named export), `rollDie(sides)` pure RNG (named export), `DieShape` SVG component (named export), `executeRoll` (the single roll engine — dice generation, advantage/disadvantage, crit/fumble detection, ~1050ms cycling-number reveal, local history, `postCharacterRoll` broadcast; ADR-027), `sessionStorage` key `dnd_dice_open_${slug}` for collapse state. `forwardRef` exposing `useImperativeHandle(ref, () => ({ rollAbility, rollAttack, getAttackExpr, advMode, setAdvMode }))`; mounted via a ref (`diceRollerRef`) in `CharacterSheetSessionMode.jsx` outside the sub-tab panels, so it stays mounted across sub-tab switches. **Story 57** — `executeRoll` gained optional parameters so a second entry point can override behavior without forking it (ADR-027): `advModeOverride` (read at BOTH the dice-math site and the `(adv)`/`(dis)` broadcast-label site — overriding only one silently drops the tag), `onComplete(resultObj|null)` (called with `null` on the pre-existing `rollState.rolling` early-return, so a caller is never left waiting with no signal), `suppressOpenPanel` (skips the `ensureOpen()` force-open side effect), and `target`/`attack` (ADR-026 pass-through to the broadcast). `rollAttack({ attackEntry, step: "atk"|"dmg", exprOverride?, advMode?, target?, attack?, onComplete, suppressOpenPanel=true })` is the Attack Bar's entry point — `attackEntry` is Story 56's `buildAttackEntries()` shape (`toHit` a bare signed bonus, `damage` a dice expression, ADR-025), so this is a field lookup into the same `executeRoll`, not a second parser; `exprOverride` (the bar's editable-expression affordance) replaces the entry's own toHit/damage entirely and is parsed with the same `parseDiceExpr`. `getAttackExpr(attackEntry, step)` computes the loaded expression string (e.g. a weapon's `"+7"` toHit becomes `"1d20+7"`) so the bar can display/pre-fill it identically to what `rollAttack` itself would roll.
- `src/components/DmDiceRoller.jsx` — DM-specific dice roller rendered at the bottom of the party column in `DmDashboardPage`. Props: `{ pal, party, onApplyDamage }`. Reuses `parseDiceExpr`, `rollDie`, `DieShape` from `DiceRoller.jsx`. New DM behaviors: ×N repeat (1–8, single 600ms animation then labeled result rows), adv/dis auto-reset to Normal after each roll, "Apply to…" pill row after pure damage rolls (no d20) that calls `onApplyDamage(slug, amount)`. `sessionStorage` key `dnd_dice_dm_open` for collapse state (no slug — DM dashboard has no character context). Does not participate in Story 57's declared-attack flow (player-only).
- `src/api.js` — all API calls; uses `VITE_API_URL` env var; password sent via `x-character-password` header
  - `VITE_WS_URL` (optional, **Story 36**) — read directly by `src/lib/useSessionSocket.js`, not by `api.js`; the `wss://` URL output as `WsUrl` from `sam deploy`. Absent in `.env` → the WebSocket nudge channel is entirely disabled and the app falls back to ADR-011 polling unchanged; this is the expected state until the WS stack is deployed and the URL is filled in.
  - `VITE_BUILD_VERSION` (optional, **Story 36b**) — read directly by `src/lib/staleClient.js`, not by `api.js`; the build's git short hash, set by `deploy.sh`. Absent (local `npm run dev`) → the stale-client auto-refresh feature is a complete no-op.
  - `getDmParty(dmPassword)` — GET /dm/party; requires DM password header
  - `patchSession(slug, fields, password)` — PATCH /characters/{slug}/session; password optional
  - `patchDmNote(slug, action, dmPassword)` — PATCH /characters/{slug}/dm-notes; DM auth required; action is `{ action: "add", text }` or `{ action: "delete", id }`
  - `getInitiative(dmPassword)` — GET /initiative; requires DM password
  - `putInitiative(dmPassword, data)` — PUT /initiative; requires DM password
  - `getMapLibrary()` — GET /maps; no auth; returns `{ activeMapId, maps[] }`
  - `presignMap(filename, contentType, dmPassword)` — POST /maps/presign; DM auth
  - `postMap(mapData, dmPassword)` — POST /maps; DM auth; registers map after S3 upload
  - `putMapActive(mapId, dmPassword, modeOpts)` — PUT /maps/active; DM auth; sets or clears (`null`) active map; `modeOpts` may include `adventureMapId`/`battleMapId` (map-bookmark assignment) and, **ADR-029**, `combatMode: boolean` — the single persisted source of truth for "is battle mode active," read by `MapPanel.jsx` and `CharacterModePage.jsx`'s `isBattleMode`
  - `patchMap(mapId, name, dmPassword)` — PATCH /maps/{mapId}; DM auth; renames map
  - `deleteMap(mapId, dmPassword)` — DELETE /maps/{mapId}; DM auth; removes from DB + S3
  - `getNpcLibrary(dmPassword)` — GET /npc-library; DM auth; returns `{ templates: [{ id, name, abilities: string[], hpMax?, portraitUrl?, updatedAt }] }`
  - `putNpcLibrary(dmPassword, templates)` — PUT /npc-library; DM auth; full array replacement; body `{ templates }`
  - `presignNpcPortrait(filename, contentType, size, dmPassword)` — POST /npc-library/portraits/presign; DM auth; image-only, 5 MB cap; returns `{ uploadUrl, id, s3Key, portraitUrl }`
  - `getCounterWheels(dmPassword)` — GET /counter-wheels; DM auth; returns `{ wheels: [{ id, name, segments, filledCount }] }`
  - `putCounterWheels(dmPassword, wheels, wheelEvent?)` — PUT /counter-wheels; DM auth; full array replacement; optional `wheelEvent: { name, segments }` causes handler to append a `type: "wheel"` roll-history entry
  - `patchMapTokens(mapId, payload, dmPassword)` — PATCH /maps/{mapId}/tokens; DM auth; replaces the `tokens[]` array on a map entry; each token may carry an optional `scale` field (0.5–3.0, Story 44 per-token resize). The per-map `mapMode` field this endpoint used to also accept was retired (ADR-029) — see `putMapActive`'s `combatMode` param above
  - `putMapCalibration(mapId, tokenScale, dmPassword)` — PATCH /maps/{mapId}/calibration; DM auth; sets `tokenScale` (0.5–2.5, server-clamped) on a map entry; called debounced 600ms from the calibration popover (Story 29b)
  - `putMapRotation(mapId, rotation, dmPassword)` — PATCH /maps/{mapId}/rotation; DM auth; sets `rotation` (0 | 90 | 180 | 270) on a map entry; called debounced 600ms from MapPanel's ↺/↻ buttons (Story 45)
  - `moveMapToken(mapId, tokenId, x, y, slug)` — PATCH /maps/{mapId}/tokens/{tokenId}/position; no auth; a player dragging their own token (Story 34); server rejects mismatched `slug` or non-character tokens with 403
  - `postCharacterRoll(payload)` — POST /rolls (fire-and-forget, unauthenticated, ADR-005); payload carries `label`, `total`, `dice[]`, `characterName`, `isCrit?`, `isFumble?`, and (**Story 57**) two optional structured fields, `target?: { type, sourceId, name }` and `attack?: { kind, id, name }` — declared-attack provenance for the shared roll feed (ADR-026); never baked into `label`.
  - `getSessionState({ dmPassword, slug })` — GET /session-state; **Story 35** (extended in **Story 35b**, **Story 36b**), the single consolidated polling endpoint. `DmDashboardPage.jsx`, `CharacterModePage.jsx`, `CharacterPage.jsx`, and `MapViewerPage.jsx` each poll this via one `useAdaptivePolling` instance instead of separate per-resource endpoint calls (5, 4, 2, and 1 respectively before consolidation) — every polled page in the app now issues exactly one HTTP request per poll tick. DM variant (pass `dmPassword`): `{ party, initiative, npcCombat, rollHistory, mapLibrary, counterWheels, serverTime, buildVersion }`. Public variant (omit `dmPassword`, optionally pass `slug`): `{ partyStatus, initiativePublic, mapLibrary, rollHistory, serverTime, buildVersion, character? }`. `buildVersion` (Story 36b) is reported to `src/lib/staleClient.js`'s `reportServerBuildVersion()` by every one of the four polling pages; `null` until the `app-meta` sentinel is written by a 36b-or-later `deploy.sh` run. `CharacterPage.jsx` passes `slug` plus whichever credential is cached in `sessionStorage` (`dnd_dm_password` takes precedence over `dnd_char_${slug}`, read fresh on every tick) so the owner/DM sees `playerNotes` as soon as the sheet is unlocked; `MapViewerPage.jsx` uses the public variant with no `slug`. The old per-resource endpoints (`getDmParty`, `getInitiative`, `getNpcCombat`, `getRollHistory`, `getMapLibrary`, `getCharacter`, `getPartyStatus`, `getInitiativePublic`) remain in `api.js` and are still used by true one-shot fetch surfaces (`MapLibraryPage.jsx`, NPC library, counter wheels, the DM dashboard's mount-time auth check) — deprecated for polling use only, not removed.
- `src/lib/useSessionSocket.js` (**Story 36** — WebSocket nudge channel, extended **Story 36b**) — `useSessionSocket(onChanged)` connects to `VITE_WS_URL`; on a `{"type":"changed"}` push it calls `onChanged` (the page's queued refetch of `GET /session-state`); on a `{"type":"reload"}` push it calls `src/lib/staleClient.js`'s `handleReloadBroadcast()` directly instead (Story 36b — does not go through `onChanged`); exponential backoff reconnect (1s → 30s cap); socket only open while `document.visibilityState === "visible"` (closes on hidden, reopens on visible); exposes `{ connected }`. If `VITE_WS_URL` is unset, the hook is a complete no-op and always returns `{ connected: false }` — callers keep today's ADR-011 polling cadence unchanged. Wired into `DmDashboardPage.jsx` and `CharacterModePage.jsx`: while `connected`, each page's `useAdaptivePolling` `activeMs` stretches from `ACTIVE_POLL_MS` (1s) to `BACKGROUND_POLL_MS` (30s) as a safety net; a nudge still triggers an immediate `queueRefresh(0)`. Both pages (and `CharacterSheetSessionMode.jsx`'s session-mode top bar, via a `wsConnected` prop passed down from `CharacterModePage`) render a small pulsing-dot "Live"/"Polling" indicator in the top bar (`.dm-pulse-dot` on the DM dashboard, `.cs-live-dot`/`.cs-live-indicator` in `characterSheet.css` for the player sheet) — purely cosmetic, no behavior depends on it.
- `src/lib/staleClient.js` (**Story 36b** — stale-client auto-refresh) — single owner of "should this tab reload itself, and when is it safe". `reportServerBuildVersion(serverBuildVersion)`: compares against the embedded `VITE_BUILD_VERSION`; schedules a reload on mismatch. `handleReloadBroadcast()`: same reload path, called from `useSessionSocket.js` on a `{"type":"reload"}` message, bypassing the version compare. Both funnel through one safe-reload routine: deferred while a text input/textarea is focused or a modal overlay is open (heuristic: any element with a className containing `"overlay"`, matching every existing modal's backdrop class — `modal-overlay`, `cc-modal-overlay`, `eg-modal-overlay`, etc.), retried every second until safe; guarded by a `sessionStorage` loop guard (`dnd_reloaded_for_<version>`, or the fixed target `"broadcast"` for a WebSocket push) capping reloads to once per target per tab per 5 minutes. Complete no-op when `VITE_BUILD_VERSION` is absent (local dev). Consumed by `DmDashboardPage.jsx`, `CharacterModePage.jsx`, `CharacterPage.jsx`, `MapViewerPage.jsx` (all four call `reportServerBuildVersion` on their `GET /session-state` response), and `useSessionSocket.js`.
- `src/features/maps/MapViewer.jsx` — reusable pan/zoom image viewer; props: `{ imageUrl, name, height, pal, tokens?, tokenScale?, tokenLayerChildren?, onTokenLayerClick?, onTokenClick?, interactionMode?, panSuppressedRef?, rotation? }`; pure CSS transform, no canvas/library; used on character sheet Map tab and DM dashboard MapPanel; when `tokenLayerChildren` is passed it renders an absolutely-positioned token overlay sized to the image's natural dimensions, with `--token-scale-multiplier` and `--map-rotation` set inline on the token layer div; `rotation` (0|90|180|270, Story 45) is appended to the inner div's transform as `rotate(Xdeg)` with `transform-origin: center`; the `onTokenLayerClick` handler converts click coordinates from visual (rotated) space back to natural image fractions before calling back — callers always receive natural-image (x,y) regardless of rotation; `panSuppressedRef` (Story 34) is an optional ref whose `.current === true` disables the mouse/touch pan handlers, used while a player drags their own token. Pan/pinch use Mouse/Touch events on the container (`touch-action: none`); this is a separate event family from `TokenChip`'s Pointer events — both fire independently (ADR-028).
- `src/features/dmDashboard/battleMode/BattleModeController.jsx` — exports `TokenChip` (shared token-rendering component used by both the DM map and the player Map sub-tab, renders PC and NPC portraits, player-only poll-move animation, DM-only Pointer-Events long-press remove) and `HeldTokenFloater` (cursor-following ghost token while the DM is placing/moving a token, rendered via portal). Story 34 — `TokenChip` also accepts `ownSlug`, `onMoveToken`, and `panSuppressedRef` (all undefined/no-op for DM-side chips): when `token.type === "character" && token.sourceId === ownSlug` the chip becomes drag-enabled via Pointer Events (own-token affordance ring, drag scale/shadow, optimistic move with animated revert on failure), calling `onMoveToken(tokenId, x, y)` on drop; player drag handler reads `--map-rotation` from the token layer's computed style to convert drag coordinates from visual space to natural image space. **Story 44 — per-token resize**: `TokenChip` accepts `onResizeToken` prop (DM + NPC only); long-press menu shows ⤢ Resize option; resize mode shows a 5-notch stepper (SIZE_STEPS = [0.5, 1.0, 1.5, 2.0, 3.0] mapped to Tiny/Medium/Large/Huge/Gargantuan labels); `--token-size-mult` CSS var drives all chip scale() expressions in battleMode.css; keyboard +/=/- step, Escape dismiss, outside-tap dismiss. DM long-press uses `LONG_PRESS_MS = 480` and cancels on `onPointerLeave` (no movement threshold). **Token counter-rotation (Story 45)**: all 6 transform declarations in `.token-chip` (base + 5 animation keyframes) append `rotate(calc(0deg - var(--map-rotation, 0deg)))` so portraits and labels stay upright regardless of map rotation; the `rotate` CSS property is NOT used (it applies before `transform`, which would break positioning). **Stories 52–54 — token effects cluster (damage flash, condition badges, invisible veil)**: `TokenChip` accepts `damageState` (`{ phaseAFresh, phaseBLive, tier, lastDamageAmount, delayMs, washOnly }` — resolved once per token in the parent via `tokenEffects.js`'s `resolveDamageState`, never inside `TokenChip` itself, which is `memo`'d and would otherwise recompute per chip on every pan frame), `condBand` (`"full"|"two"|"one"|"none"`, the Story 53 badge-slot count, resolved in the parent from `computeEffectivePx`/`resolveCondBand`), `veil` (`{ veiled, secret }`, driven only by the server-computed `token.invisible` flag — never re-derived from `conditions[]` client-side), `shimmerDelayMs`, and `exiting` (renders the Story 54 NPC-vanish ghost, `pointer-events: none`, no interaction handlers attached). A new inner `.tk-hit` wrapper (child of `.token-chip`, not an ancestor — see `battleMode.css`'s file-header note) carries Story 52's recoil and Story 54's vanish transform independently of `.token-chip`'s own transform. `ConditionGlyphSprite.jsx` renders the 14-condition SVG glyph sprite once per map surface (not once per token) for badge `<use>` references. **Story 57 — player-facing hold-to-target on NPC tokens**: `TokenChip` accepts `onTargetToken(tokenId)` (player-only, NPC-only; undefined for DM chips and absent when targeting isn't armed) and `targeted` (boolean per chip, driven by the caller comparing `token.id` against the current declaration). `handlePointerDown`'s old early-return for a player on an NPC token (`if (!isDm || isHeld) return;`) is now preceded by a `canTarget` branch that starts a 500ms (`TARGET_HOLD_MS`, independently named from the DM's `LONG_PRESS_MS = 480`) hold timer; `canDrag` is own-PC-only so there is no collision with Story 34's drag. The 8px (`TARGET_MOVE_CANCEL_PX`) movement threshold is a *cancel* condition on the chip's own pointer-gesture timer tracked in `handlePointerMove`, not a routing decision (ADR-028) — `panSuppressedRef` is never set by this gesture (only drags set it); a committed hold sets `suppressClickRef.current = true`; and `handleMouseEnter` is suppressed while `targetCharge === "charging"` (same one-line-guard precedent as Story 44's `resizeActive` check). Renders `.tk-target-charge-ring`/`.tk-target-charge-dot` (charge sweep, reuses `.token-longpress-ring`'s stroke-dashoffset mechanism under new class names) while charging, and `.tk-target-ring` (the reticle — a dasharray-gapped circle, same technique as `.tk-veil-ring`) while `targeted`.
- `src/features/dmDashboard/battleMode/tokenEffects.js` (Stories 52–54) — the single shared module for the token-effects cluster, consumed by both `MapPanel.jsx` (DM) and `PlayerMapViewer` (`CharacterSheetSessionMode.jsx`, player). Exports: `resolveDamageState()` (per-token freshness gate + Phase A/B liveness, mutates a caller-owned `Map<tokenId, lastSeenStamp>` — called from a `useEffect`, not during render, since refs may only be touched outside render), `resolveIntensityTier()`, `isPhaseBLive()`, `assignAoEStagger()` (70ms stagger, 6-token cap), `getBadgeEligibleConditions()`/`resolveConditionMeta()` (the condition→family/rank/glyph table, `Exhaustion` folded in as a synthetic entry, stable index-keyed priority sort), `resolveCondBand()`/`computeEffectivePx()` (Story 53's size-band resolver, reused unchanged by Story 54's veil ladder), `isInvisibleCondition()`, `shimmerPhaseOffsetMs()` (deterministic per-token djb2 hash, same approach as `tokenUtils.js`'s `npcInitialColor`), `useDebouncedValue()` (80ms, used on the shared zoom value so every token's band changes on the same tick), and `useTokenExitGhosts()` (the Story 54 NPC-vanish diff registry: a token present last render and absent this render — an invisible NPC server-omitted from the payload — renders as a 500ms fading ghost instead of an instant DOM removal; scoped to NPC tokens only, since a PC token disappearing because `partyVisibilityEnabled` toggled off is a privacy setting, not "it went invisible"). Both `MapPanel.jsx` and `PlayerMapViewer` resolve this per-token state in a `useEffect` + `useState` (not `useMemo`, since the computation reads/mutates a ref) keyed on the coarse inputs that actually change on a poll tick (party/npcCombat/serverTime/initiative/tokenScale/debouncedZoom) — not on `viewerState`, whose translate/scale change on every pan frame — so the resolved objects keep a stable identity across pure pan/zoom renders and `TokenChip`'s `memo()` keeps working.
- `src/features/dmDashboard/MapPanel.jsx` — DM map panel; token placement/held-state machine, the ⚙ token-scale calibration popover (`CalibrationPopover.jsx`, Story 29b), per-token resize (`handleResizeToken` → debounced 300ms `patchMapTokens`, Story 44), and map rotation (`handleRotate(delta)` → optimistic `localRotation` + debounced 600ms `putMapRotation`, Story 45); ↺/↻ buttons in the map header rotate by 90° steps; token tray `⋯` menu: "Clear Tokens from Map" (removes all tokens from map), "Clear NPCs from Map" (keeps PC tokens, removes NPC tokens), "Cancel". **ADR-029** — `isBattleMode` is derived directly from the `combatMode` prop (passed down from `DmDashboardPage.jsx`'s own combat-mode state/chrome), the single persisted source of truth; the panel no longer owns its own Battle Mode toggle button, per-map `mapMode` field, or optimistic `localMapMode` override — those were retired along with `BattleModeToggle.jsx` (deleted) and the dead `onRegisterBattleToggle`/`battleToggleFnRef` wiring into `DmDashboardPage.jsx`. **Stories 52–54** — accepts new `serverTime`/`initiative` props (threaded from `DmDashboardPage.jsx`'s `getSessionState()` poll); resolves each token's `tokenEffects.js` damage/condition-band/veil state in a `useEffect`+`useState` pair (see `tokenEffects.js` above for why not `useMemo`) and passes the resolved objects into `TokenChip`; renders `ConditionGlyphSprite` once. Story 57's targeting flow does not touch this file (player-only, DM map unaffected).
- `src/features/dmDashboard/CharacterCard.jsx` — party card shell (Story 38 decomposition): header, portrait, HP bar/stepper, temp HP, status row (conditions/concentration/inspiration), spell slots, saves strip, and modal orchestration (`modalMode`, `showAwardXp`, `showDistributeCoin`). Re-exports `AwardXpModal` and `DistributeCoinModal` from `characterCard/` for backward-compatible import paths (consumed directly by `DmDashboardPage.jsx`). Owns HP optimistic-update state (`optimisticHp`/debounced flush) and the lifted `isFallen`/`isStable` death-save booleans (needed for card-level classes/opacity); everything else death-save-related lives in `DeathSavesStrip`.
  - `src/features/dmDashboard/characterCard/DeathSavesStrip.jsx` — the 0-HP strip: pips, shortcut row (Nat 20/Nat 1/Stable), damage-at-0 prompt, FALLEN tombstone state (Story 19 spec). `forwardRef` exposing `showDmgAtZeroPrompt()` for the shell's HP-stepper/DamageHealModal flows; `isFallen`/`isStable` are props (setters) lifted to the shell, everything else (pip state, shortcut disclosure, timers) is owned locally.
  - `src/features/dmDashboard/characterCard/DamageHealModal.jsx` — focused damage/heal modal (stepper, presets, direct input, Enter/Escape keyboard handling)
  - `src/features/dmDashboard/characterCard/QuickActionPopover.jsx` — the ⋯ popover (Deal Damage/Heal shortcuts, Add Condition, Set Temp HP, Drop Concentration, Short/Long Rest)
  - `src/features/dmDashboard/characterCard/DmNotesStrip.jsx` — collapsible DM notes + shared player notes strip (renamed from the card's former internal `NotesStrip`)
  - `src/features/dmDashboard/characterCard/XpCoinRow.jsx` — XP progress bar + coin panel (Tier-2 collapsible section), award/give buttons
  - `src/features/dmDashboard/characterCard/AwardXpModal.jsx`, `DistributeCoinModal.jsx` — XP award and coin distribution modals, re-exported from `CharacterCard.jsx`
- `src/pages/` — CharactersListPage (index), CharacterPage (view/edit at `/characters/:slug`), CharacterModePage (`/characters/:slug/profile` and `/characters/:slug/session` — owns data fetching for mode-routed character views), NewCharacterPage (create flow), DmDashboardPage (`/dm`), MapLibraryPage (`/maps`, DM-only)
- `src/features/characterSheet/CharacterSheetSessionMode.jsx` — session mode two-column layout component; profile mode navigates back to `CharacterPage`; all writes via `patchSession` without auth; see `design/app-overview.md` for full layout description; also owns `PlayerMapViewer`, the token-layer wrapper around `MapViewer`/`TokenChip` for the Map sub-tab — mostly read-only, except the player's own character token, which is drag-movable in battle mode (Story 34; writes via `moveMapToken`). **Stories 52–54** — accepts a new `serverTime` prop (threaded from `CharacterModePage.jsx`); `PlayerMapViewer` additionally accepts `initiativeData` and `ownCharacter` (the `?slug=` character payload already fetched by `CharacterModePage.jsx`, merged into the token-resolution `party` array so the player's own token always shows its own Story 53 badges even when `partyVisibilityEnabled` is off); resolves the same `tokenEffects.js` per-token state as `MapPanel.jsx` and additionally runs `useTokenExitGhosts()` for the Story 54 NPC-vanish fade. Mounts `DiceRoller` via `diceRollerRef` outside the sub-tab panels (the sub-tab panels toggle a CSS `.active` class and all stay mounted) so the roller — and, from Story 57, the Attack Bar/reticle — survive a sub-tab switch. **Story 57 — Attack Declaration Bar**: owns transient `declaration` state (`{ target: {tokenId,sourceId,name}, attack: {id,kind,name,toHit,damage,level}|null, lastRoll: {step,total,...}|null, gone }`, never `sessionStorage`); `handleTargetToken` is a permanently-stable `useCallback` (empty dependency array, reads live token/npc data from a ref updated in an effect) so it never defeats `PlayerMapViewer`'s/`TokenChip`'s `memo()`; passes `targetedTokenId` (a primitive tokenId string, not the declaration object) + `onTargetToken` down into `PlayerMapViewer` → `TokenChip`; a `useEffect` derives the GONE state from two consecutive poll ticks of `activeMap.tokens[]` absence; mounts `AttackDeclarationBar.jsx` (new, `src/features/characterSheet/`) fixed to the viewport bottom and `RollOverlay.jsx` (new, `src/components/`) while a roll from the bar is in flight/settling. Mirrors `DiceRoller`'s `advMode` into local state via a new `onAdvModeChange` callback prop (a ref-exposed value alone isn't reactive) so the bar's Adv/Dis strip re-renders when it changes.
- `src/features/characterSheet/AttackDeclarationBar.jsx` (**Story 57**, new) — the four-state (`pick`/`armed`/`result-atk`/`result-dmg`, plus a `gone` override) fixed bar; owns only the small amount of local UI state the editable-expression affordance (§3.4) needs (which step is being edited, the draft text, per-step expression overrides, spent-chip shake state) — every declaration state transition is a callback prop reached from `CharacterSheetSessionMode`.
- `src/components/RollOverlay.jsx` (**Story 57**, new) — the centred full-viewport roll-landing reveal, Attack-Bar-only. Purely prop-driven (`playing`/`result`/`onDismiss`); cycles a random d20 face on a 90ms interval while `playing && !result`, settles on `result.total` and auto-dismisses ~400ms later. Reuses `DiceRoller.jsx`'s exported `rollDie` and its `dr-crit-pulse`/`dr-fumble-shake` keyframes (already loaded globally via `DiceRoller.jsx`'s own `diceRoller.css` import) rather than re-deriving either.

## sessionStorage keys (full list)

`dnd_palette_${slug}`, `dnd_dm_password`, `dnd_char_${slug}` (per-character password caching), `dnd_tab_${slug}` (active tab; `"loadout"` | `"persona"` | `"combat"` | `"map"`, default `"combat"`), `dnd_dice_open_${slug}` (dice roller section open/closed, default `false`), `dnd_dice_dm_open` (DM dice roller panel open/closed, default `false`), `dnd_mode_${slug}` (character page mode; `"profile"` | `"session"`, default `"profile"`), `dnd_session_subtab_${slug}` (session mode sub-tab; `"combat"` | `"loadout"` | `"map"` | `"notes"`, default `"combat"`), `dnd_wheels_open` (counter wheels panel open/closed; `"true"` | `"false"` | absent for mode-aware default; no slug suffix — DM dashboard has no character context), `dnd_reloaded_for_<version>` (**Story 36b**; loop-guard timestamp written by `src/lib/staleClient.js`; caps stale-client auto-reload to once per target version — or the fixed target `"broadcast"` for a WebSocket reload push — per tab per 5 minutes). **Story 57's in-progress attack declaration is deliberately transient client state and is NOT stored here** — a declaration restored after a reload would misrepresent a board that has moved on.
