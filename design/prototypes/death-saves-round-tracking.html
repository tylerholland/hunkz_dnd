Use the ⚔ Damage button to reduce HP to 0 and mount the tracker. At 0 HP, apply more damage to see the inline failure prompt.

Pip grammar: Tap empty pip → fills it and all to its left. Tap filled pip → un-fills it and all to its right (instant, correction path).

③ Damage-at-0 Inline Prompt
When the DM applies damage to a character already at 0 HP, the confirm flow ends with this inline row. Default focus on [+1 Failure]. Rules-mandated: any damage at 0 HP = +1 failure; a crit or melee hit from within 5 ft = +2 failures.

④ Round Counter — Initiative Header
The round counter lives in the initiative header row. Auto-increments with a brighten flash when Next Turn wraps last→first. Manual ± uses same swap animation but NO brighten (honest distinction from a real wrap). Clear × resets to round 1.

Round counter rules
Auto-increment: fires when Next Turn wraps from last entry back to index 0. Number does translateY(-4px)→0, opacity 0.4→1, 200ms ease-out. The round number briefly brightens (accentBright flash) — signals a real round completed.

Manual ±: same number swap animation but NO brighten flash. The DM is correcting an error, not completing a round — motion language stays honest.

Clear ×: resets initiative list AND round to 1. Combat is over; next fight starts fresh.

Empty initiative: round shows — (em dash, muted), steppers disabled.

Design Notes & Annotations
①Death save tracker mounts at HP=0 via max-height + opacity transition (300ms ease-out). Unmounts on heal, stable, or death (250ms ease-in). Exception: on 3 failures, tracker stays visible — the FALLEN animation owns the card-level moment.
②Solid pip borders (not dashed) signal DM authority — this replaced the old "player-reported" dashed-ring stub. The dashed treatment communicated uncertainty; solid communicates ownership. The "player-reported" caption is deleted entirely.
③Success pip fill: scale 0.7→1.0 + opacity 0→1, 180ms ease-out, NO glow. Failure pip fill: same entrance animation THEN whole-block shake (±3px, 300ms). The asymmetry — success is calm, failure shakes — is load-bearing.
④NAT1 taps next two empty failure pips in a 60ms-staggered pair, then ONE block shake — not two shakes. If this reaches 3 failures, the FALLEN sequence fires. If no empty pips remain to fill, NAT1 does nothing (capped at 3).
⑤NAT20 sets hpCurrent=1 and clears all pips. Card red border fades to palette accent (300ms). Tracker collapses (250ms). HP number animates 0→1 with heal-glow. Stable button sets hpCurrent=0, same tracker collapse but HP stays 0 and card dims to 0.85 — visually distinct from NAT20.
⑥Pip tap grammar: tap empty pip → fills it and all pips to its left in that cluster (like spell-slot bubbles). Tap filled pip → un-fills it and all to its right (correction path, instant, no animation). This asymmetry makes correction feel different from marking.
⑦FALLEN state: card opacity → 0.6 over 600ms ease-in. Name line-through. FALLEN label fades in. Pips frozen visible (tombstone). Reversible by tapping a failure pip down — no modal confirm. Death is not irreversible in the tool; reversibility by direct manipulation replaces undo.
⑧Round counter auto-increment animation: translateY(-4px)→0, opacity 0.4→1, 200ms ease-out. PLUS accentBright color briefly brightens. Manual ± uses same swap but NO brighten — honest signal distinction between real wrap and manual correction.
⑨− stepper disabled at round 1 (visual dim + cursor not-allowed). No maximum. Clear × resets both initiative list AND round to 1 in one tap — critical correctness requirement (next fight must not inherit the previous round count).
⑩Damage-at-0 inline prompt is one extra tap inline in the existing damage flow. It does not require the DM to remember to open something separately. [+1 Failure] has default focus. [No Failure] exists for edge cases where the damage source doesn't apply (e.g., AoE from allied Fireball at 0 HP).
