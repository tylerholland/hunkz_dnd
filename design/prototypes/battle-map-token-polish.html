Section 3 of 6
Smooth Player-Side Poll Move
"Simulate poll update" moves a token to a new position with transform 280ms cubic-bezier(0.2,0.8,0.2,1). Fires only when the position changes, never on first mount. "First mount" adds a fresh token that fades in at its committed position (180ms ease-out) — no slide from origin.

Motion spec

Poll move:
transform 280ms cubic-bezier(0.2,0.8,0.2,1) — slow enough to read, fast enough to resolve before next 1s poll tick.

First mount:
opacity+scale 0→1, 180ms ease-out — appears at committed position. No slide from (0,0).

Gate:
.has-mounted class applied after first paint via a mounted flag. Transition class not present on first render.

Section 4 of 6
Long-Press Remove (Touch / Mouse Hold)
Hold a placed token for 480ms → clockwise ring-sweep charge cue → ✕ Remove / Cancel micro-menu. Releasing before 480ms cancels and resets the ring. Menu scales in 0.94→1 + opacity (140ms ease-out). Remove: token scales to 0 + fades (180ms ease-in). Works with mousedown/mouseup and touchstart/touchend. DM-only: players have no token interaction.

Strategy: replace, don't delete where motion carries meaning. The upload progress ring is kept as a static determinate indicator (real system state, not decoration).
Legend
①
Camera overlay placement — lives on the identity circle, not in ⋯ menu. Direct manipulation: tap the face to give it a face. Zero horizontal space cost.
②
Upload flow — local object-URL preview shows immediately on file selection. Progress ring tracks bytes (determinate). On success: shimmer fades (180ms), ring completes + fades. Writes portraitUrl to the live NPC combat object via putNpcCombat with no separate save step.
③
NPC ring stays neutral grey with a portrait set. The portrait carries identity; the grey ring carries faction (NPC). Only PC rings are palette-derived.
④
Calibration gear (⚙) — shown only in Battle Mode. A setup-once action does not earn permanent header real estate. Popover is 240px on desktop; full-width bottom sheet below 360px (not shown here).
⑤
Slider is live (1:1) — dragging thumb resizes tokens instantly via --token-scale-multiplier CSS variable on the MapViewer root. No token-list re-render. ± steppers give 120ms ease-out tween. Tray chips never scale.
⑥
has-mounted flag — the poll-move transition class is applied only after the token's first render. Without this gate, a newly-appeared token would slide in from (0,0) origin.
⑦
Long-press 480ms intentionally distinct from the 280ms hover-expand. At ~280ms the hover-expand card cross-fades out (120ms) as the charge ring takes over. Releasing early always cancels; ring resets instantly.
⑧
Tray "ALL PLACED" requires total > 0. An empty tray (0 total tokens) shows Story 29's empty-state copy. Collapse trigger: unplacedCount === 0 && total > 0.
⑨
Reduced-motion strategy — single authoritative block in tokens.css. Blanket animation: none; transition-duration: 0ms on all token-layer elements. Upload progress ring kept as static determinate indicator (real system state).
⑩
Story 31 contract — portraitUrl is the same field Story 31's library entries store. "Save to library" is a one-way snapshot at save time. Spawning a library entry pre-fills the portrait — no second upload.
