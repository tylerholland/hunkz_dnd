Design Notes
①Fill model: fill-to-here clockwise (Blades-classic). Tapping segment N sets `filledCount = N` if empty, or `filledCount = N-1` if already filled and you tap it again. Stored as a single number, not a boolean array.
②Each wheel is full pie slices (center-to-rim), not thin arcs — maximizes tap target and bold fill read at small sizes. Constant 2–3° gaps regardless of segment count keep the "clock" read consistent from 2 to 12 segments.
③Segment fill: 160ms ease-out (color + glow bloom + 0.92→1.0 scale). Unfill: 200ms ease-in (90ms glow collapse then 110ms fade-out). Full-wheel completion: one-time 420ms ease-in-out pulse (0.45→0.9→0.6 opacity, 1.0→1.04→1.0 scale), then holds at steady elevated glow.
④Reset performs a clockwise de-fill sweep, each filled slice emptying staggered 25ms from 12 o'clock — implemented via incremental setTimeout per segment, total duration 90ms + 25ms × filledCount.
⑤Single-segment wheel (Scenario 6) renders as a full ring with a 2–3° notch at 12 o'clock. Tap toggles between filledCount 0 and 1 — a binary clock.
⑥Mode-aware expand/collapse default is simulated via two static scenario panels (collapsed vs. expanded) rather than a live mode toggle, since the brief's "combat mode" trigger lives outside this panel's scope (initiative state). The manual-toggle-wins persistence (`dnd_wheels_open`) is demonstrated by each panel's header click toggling independently.
⑦Remove has no confirmation (resolved open question) — single click deletes, separated from Rename/Reset by a divider and styled in universal error red `#c06060` so it isn't tapped by accident.
⑧Activity log entries fire only on creation, formatted `◷ [name] — N segments` with no numeric total — visually distinct from dice rows so the feed doesn't read as "another roll."
⑨Panel body caps at `min(40vh, 360px)` with internal scroll once wheels exceed the visible row count, so Counter Wheels (Tier 2) never crowds out the Tier-1 party card strip below it.
⑩Implied by design-system conventions (not explicit in brief): the wheel cell itself has a 150ms hover-independent entrance via `wheelCellIn` for new wheels; the menu popover close-on-outside-click is standard popover behavior matching the party-card ⋯ pattern.
