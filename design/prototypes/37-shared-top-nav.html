Scenario 3 of 3
Shared primitive reuse — map-mode toggle
The same segmented-control primitive that renders the ❡ Profile / ⚔ Session mode toggle in the top nav is reused here, unchanged in spec (~32px visual capsule height, 44px hit area, hairline mid-divider, --pal-accent-dim fill on the active half, --pal-text-muted on the inactive half), for the DM dashboard's Adventure / Battle map-mode toggle.
Lives in the map panel, not the top nav — Battle Mode is shared world state (every player sees the same map mode at once), not a personal per-user navigation choice like Profile/Session.
Legend — non-obvious decisions
1
Back glyph — quiet ‹, 44px target, --pal-text-muted brightening to --pal-accent-bright on hover. Hidden entirely on the library root (no back target exists). Demotes the old shouting ← ALL CHARACTERS label.
2
Title is identity, not a button — Cinzel small-caps ~15px, never clickable, never styled as an action. Pairs with the back glyph on the left and survives truncation on mobile via text-overflow:ellipsis.
3
Mode toggle is one segmented-control capsule, not two separate buttons — 1px --pal-border around the whole capsule (radius on the container, not per-segment), a hairline divider between halves, active half filled --pal-accent-dim + --pal-text, inactive half transparent + --pal-text-muted. Revised again per DM review: the visual capsule is now a slimmer ~32px tall (11px label, tighter padding) instead of the original 44px-tall pill — but each segment keeps a 44px-tall invisible ::before hit area centered over it, so tap accuracy doesn't shrink even though the pill looks lighter. Only renders on character surfaces. Desktop: centered in the bar. Below 560px (via CSS container query on the demo frame's own width, not the viewport): the whole capsule drops to a second sticky row, still in sync with its desktop twin.
4
Live/Polling dot only appears on the three surfaces that actually poll GET /session-state: Character Sheet, Session Mode, DM Dashboard. Library and Map Library are one-shot fetches — no dot, per app-overview.md.
5
World Guide book icon appears on all six contexts — this is a deliberate reading of "same slots on every page" / "all surfaces incl. session mode." It's new on Session Mode (the story's explicit fix) and also new on both Library states and Map Library, which never had it before. Flagged as an assumption worth confirming, since the nav audit table didn't show a book icon on those three today.
6
⋯ context menu — one spec everywhere: --pal-surface-solid panel, 8px radius, 40px rows, 13px IM Fell English, 1px --pal-border dividers, destructive rows in universal #c06060 (not palette-derived). Anchored top-right under the trigger, opens with a 150ms fade + 6px slide, closes on outside click or re-trigger.
7
Manage Party / Upload stay dedicated bar buttons — both are high-frequency actions and explicitly exempted from the ⋯ consolidation. On mobile they're dropped entirely ("nothing else" per the mobile spec) rather than shrunk, matching the same width-pressure lesson that already pulled Short/Long Rest off the DM dashboard bar.
8
Export JSON moved into ⋯ (rare action, no longer permanent chrome) and Edit Character left the bar entirely for the profile page body (Story 42) — neither appears as nav chrome anywhere in this prototype, by design.
9
Palette cascade — the exact same TopNav markup/CSS re-tints via --pal-* custom properties set once on each surface's root, per ADR-014. Character surfaces get the character's own palette (vellum shown); DM surfaces get campaign Ocean.
10
Mobile (<560px) — only ‹ + title (left) and dot + book + ⋯ (right) survive; the segmented mode toggle relocates to a second row, page-specific bar buttons (Manage Party / Upload) disappear entirely. Every remaining target stays ≥44×44px (visual capsule may be 32px, but the tap area underneath is not); no horizontal overflow at 375px.
11
Segmented control is a shared primitive, not nav-specific markup (Scenario 3) — the DM dashboard's in-panel Adventure/Battle map-mode toggle reuses the identical .topnav-segment/.topnav-seg-btn spec, sizing, and Ocean tokens, but intentionally stays inside the map panel rather than moving into the shared nav, since map mode is shared world state rather than a per-user navigation choice.
