Section 2 of 5
Reticle Anatomy — §3.1
Four diagonal 60° arcs centred at 45°/135°/225°/315°, radius = faction-ring radius + 3px. The N/E/S/W gaps are deliberate clearance for Story 54's ◇ slot (12 o'clock) and Story 53's left-edge badge column (9 o'clock). Tinted with the viewing player's own --pal-accent-bright, not a universal colour — this is private intent, not a shared board truth.
Underlay stroke — rgba(0,0,0,0.55), 3px, sits beneath the tinted stroke so the reticle reads on any of the 8 palettes and against any terrain.
Accent stroke — var(--pal-accent-bright), 1.5px, linecap round. The viewing player's own colour — "this is mine."
N/E/S/W gaps — 0°/90°/180°/270° stay clear year-round for Story 54's ◇ marker and Story 53's condition badge column.
Lives inside .token-chip — inherits Story 45's counter-rotation automatically; no correction code needed at any of the four map rotations.
Entrance — group scale 1.25→1.0 + per-arc stroke-dashoffset draw from each arc's midpoint outward, 200ms cubic-bezier(0.2,0.8,0.2,1). "The arcs converging is the lock."
At rest — opacity 0.70↔1.00 breathe, 2.4s ease-in-out infinite alternate. Ambient — readable without looking directly at it.

Section 4 of 5
The Gesture Discriminator — §7.1
The single most load-bearing pair of constants in the brief. Try it live in Section 1 — press an NPC token and watch the HUD count elapsed ms and moved px in real time before you release.
Gesture on an NPC tokenThresholdResult
pointerdown → up<500ms, <8pxDeclare target (or untarget if already targeted, PICK only)
pointerdown → up≥500ms, <8pxExisting hover/long-press detail card (Story 53) — no targeting
pointer moves>8pxMap pan (unchanged) — never a declare, regardless of duration
This inverts today's tap-priority on enemy tokens deliberately — on a combat surface the fast, cheap gesture belongs to the frequent action, inspection is the rare one. Zero collision with Story 34: targeting is NPC-only, dragging is own-PC-only, and PC tokens (Eoghan, below-left) are completely untouched by this story — try tapping Eoghan's own token to see the unchanged behaviour.
Section 5 of 5
Size-Degradation Ladder — §9
The Roll button, the target name, and the result total never truncate at any step — they're the reason the bar exists. Everything else absorbs the squeeze first.
Legend / Implementation Notes
1The Attack Bar and Roll Overlay are scoped to the demo-frame viewport (Section 1's dashed boundary), not the real browser viewport, purely so the rest of this review page stays usable — dimensions, opacity, and z-index stacking are otherwise faithful to the brief.
2"Simulate Target Gone" fires the GONE sequence immediately for reviewability; in the real app this triggers only after two consecutive poll ticks of absence (§8), which this prototype does not simulate polling for.
3Fake/canned roll math throughout, as directed — no real dice probability. The "Next Roll" selector force-picks Normal/Crit(Nat 20)/Fumble(Nat 1) so both treatments are reachable on demand.
4Crit gold / fumble red colours and the 420ms glow/shake keyframes are reused verbatim from the existing dice roller prototype (design/prototypes/dice-roller.html) — no new roll-state colours invented.
5"Battle Mode Active" / "Has Rollable Attacks" toggles demo edge cases #1 and #2 (§10) — with either off, NPC tokens fall back to today's plain tap→detail-card behaviour and the bar never mounts.
6Goblin 2 is pre-set to 0 HP (downed tint) to demonstrate edge case #4 — declaring against a downed target still works; the app never adjudicates death.
7"Next Turn" only advances a cosmetic round counter — it deliberately does not clear a live declaration, demonstrating edge case #7 (opportunity attacks survive turn changes).
8"⟲ Rotate Map 90°" rotates the whole canvas while every token (and therefore its reticle, which lives inside it) counter-rotates to stay upright, at all four rotations, with no reticle-specific code.
9The picker → chosen-chip transition is an approximated crossfade/pulse choreography rather than true FLIP position interpolation (see top-of-file HTML comment) — timing windows match the brief exactly; exact chip-to-slot translation is a production refinement.
10Section 3's states strip and Section 5's ladder render the same .cs-atk-bar markup/CSS as the live demo, statically, for at-a-glance review without performing the full gesture flow.
