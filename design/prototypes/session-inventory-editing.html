Implementation notes — revision 4

  • Revision 4 — row-height bug fix. Root cause: .cs-sm-ld-list's align-items: center centers each of a row's five cells within their shared grid track, but never equalizes their height — each cell is still sized to its own content. A plain/empty text cell is ~17-20px tall; .cs-sm-ld-type-chip's own padding+border made it ~38px tall. Since a row's track height is the max of its cells, only rows that happened to have a category set (Potion of Healing, Cloak of Elvenkind) got a taller track than chip-less rows (Rations, Backpack) — the same kind of row rendering at two different heights depending on incidental content, and (less visibly) each cell's own border-bottom landing at a slightly different vertical offset within that shared track since centering ≠ equal height. Fixed by giving .cs-sm-ld-cell itself a uniform min-height: 44px (also the project's own touch-target floor) plus display: flex; align-items: center so every cell in every row reaches the same floor regardless of content, and content centers within that fixed height instead of relying on line-height/padding math. Verified with a script measuring every cell's rendered height at all three width presets (238/288/350) plus the long-name row — uniform 44px in every case, name-cell text-overflow: ellipsis confirmed still truncating correctly as a flex item (it doesn't wrap; the "wrapped" long name in question always truncates on one line, by design — see the white-space: nowrap rule below).
  • Revision 4 — general cleanup. Reduced .cs-sm-ld-type-chip's own padding slightly (now cosmetic only, since row height no longer depends on it) for a lighter badge. Added a subtle var(--pal-surface) tint, rounded bottom corners, and right-hand padding (there was none — description text ran flush to the frame edge) to .cs-sm-ld-expand, so the tap-to-expand detail area reads as a self-contained drawer rather than more flat list rows. Added a hover color shift on the row's tappable cells (name/qty/category/chevron) — a visual affordance only, no new handler, since none of this text previously signaled it was interactive to a pointer user. No markup/JS/interaction changes beyond that; all mock behavior (equip toggle, potion Use, drop confirm, compose row, coin pad) re-verified working after the CSS pass.
  • What changed from rev 1, and why: rev 1 matched the CURRENT live Session Loadout column exactly (name + qty, nothing else) because that's what's actually in production today. But that's the bug — the live Session column is missing interactions that already exist and already work, unauthenticated, in the classic sheet's own Inventory tab (CharacterSheetViewMode.jsx): equip/unequip toggle, an attunement dot, a type category, a potion "Use" button, tap-to-expand for description, and Drop Item. Session mode never got a version of that row — it got a read-only summary instead. This revision ports that existing, already-no-auth-safe row logic into Session mode rather than inventing anything new.
  • Row layout is real columns, not a stacked summary (revision 3). An earlier pass of this prototype put the category behind the same tap-to-expand as the description, to dodge crowding at the 238px worst case. Feedback on that pass: desktop routinely has roughly double that width, and hiding an at-a-glance fact (what kind of item this is) behind a tap just because the worst case is narrow was the wrong trade. Fixed by making .cs-sm-ld-list itself a CSS grid (20px minmax(0,1fr) auto auto 20px) with each row's five cells as direct grid children (via display:contents on the row wrapper) — equip dot, name, qty, category, and the expand chevron are genuine aligned columns down the whole list, sized from the widest content across every row, not per-row guesses. Only description/effects text and the Use/Drop actions stay behind the expand tap — those are "look it up when you need it," unlike category which is "glance at it every time."
  • Equip/unequip — tap the circle (leftmost column) to toggle: filled means equipped, an outlined empty ring means not. Mirrors toggleEquipped in CharacterSheetViewMode.jsx exactly: sets equipped: false/true, no confirm, optimistic. Unequipped items' names also dim, matching the existing dimming rule.
  • Category — reuses the real ITEM_TYPE_OPTIONS from ItemEditorModal.jsx verbatim (Armor / Shield / Wondrous / Potion / Tool / Ammunition / Quest / Other). Shown as its own column, only when set — an item with no category just leaves that cell blank, it doesn't collapse the column (the point of a real column is that it stays put). Set at creation via the compose row's "⋯ More" panel, or (in the real implementation) editable later via the existing modal — this prototype doesn't rebuild item editing for existing rows, per the brief's own out-of-scope line.
  • "Use" (potions) — shown only when type === "potion" and qty > 0. Tapping it does exactly what usePotion() already does in the classic sheet today: decrement qty by 1. It does not auto-roll or auto-apply healing — the player still applies HP themselves via the existing HP control. This matches the app's existing trust model (nothing auto-computes an effect from freeform description text) and is the same behavior already live in the classic Inventory tab, just reachable from Session mode too. Try it on the Potion of Healing row.
  • Drop Item — behind the same tap-to-expand as description, with the same two-step confirm (Drop Item → Confirm drop / Cancel) as the classic row. No swipe-to-delete, per the brief's explicit non-interaction list.
  • Description is now visible — tap any row with description text to expand it. Previously this data existed on the item but was never rendered anywhere in Session mode; now it is, matching the classic sheet's own tap-to-expand pattern (not a new one).
  • Adding a description/category on create — the compose row's "⋯ More" toggle (replacing rev 1's inert placeholder note) reveals a real category <select> and a description <textarea> inline, and both are included on the new item when you tap Add. In the real implementation this is still the seeded ItemEditorModal escalation the brief specs (§8) — inlined here only because building a second real modal wasn't worth it for a prototype when the fields are simple enough to show directly.
  • Closing the compose row without adding — a small ✕ now sits top-right of the open compose row and closes it immediately, text and all. Escape and blur-when-empty (both already specced) still work too; the ✕ exists because neither of those is discoverable by looking at the row, which was the actual complaint.
  • Coin editor — dropped = SET. Only − Spend / + Gain remain. Setting an absolute total doesn't correspond to anything that happens at the table (you either spend or you find gold) and it was the segment most likely to be tapped by mistake right next to Gain. Chip-accumulation and rebase-at-commit are unchanged.
  • Local mock state only — nothing here calls patchSession; "writes" mutate an in-memory array/number and re-render.
  • Repeat-capture: after Add (click or Enter) the input clears and keeps focus instantly. The "⋯ More" panel also collapses and resets after each add — category/description are per-item, not sticky across a bulk-add streak (an assumption, flagged as such since the brief doesn't specify this case).
  • Comma-bulk: "Rope, Torch, Rations" + Enter creates 3 rows using .cs-spell-row-enter verbatim (140ms ease-out, opacity+translateY(-4px→0)) with a 40ms stagger capped at index 5, matching Story 56's constants exactly. When "⋯ More" is open during a bulk add, the typed category/description apply only to a single (non-comma) add — same precedent as the qty chip below.
  • Trailing quantity parse: a trailing " x20" / " ×20" (case-insensitive) sets qty and is stripped from the name. Only a trailing match parses. Applied per comma-segment.
  • Qty chip vs. typed xN: if both are present on a single (non-comma) add, the parsed xN wins.
  • Empty/whitespace name disables Add (0.4 opacity) and Enter no-ops; empty comma segments are dropped silently; name is hard-capped at 60 characters.
  • Negative guard: Spend larger than the current balance clamps to 0 and flashes the numeral red (400ms) rather than going negative.
  • Drift demo: use the harness button while the pad is open to see the base rebase, the pending amount survive, and the inline note appear; Apply then resolves against the drifted total.
  • Write-failure path (harness toggle): the optimistic row fades out, the compose row reopens with the typed text restored, and the border holds #c06060 for 900ms with a tap-to-retry line.
  • prefers-reduced-motion: reduce is respected throughout.
  • Not covered by this story, flagged separately: action-economy / class feature usage ("abilities carrying over from the first page" — Rage, Second Wind, limited-use features) is a different capability than inventory item use and isn't built here. It isn't Story 61 either (that story is about a player viewing a teammate's abilities, not using your own). Recommend it as its own future story rather than folding it into Story 58's inventory scope.
